# fbvector: Extensive Examples & Integration Guide

This guide provides real-world examples, advanced SQL queries, application integration code, and optimization strategies for the `fbvector` Firebird extension.

---

## 1. Schema Design: BLOB vs. VARCHAR

When storing vector embeddings in Firebird, you have two primary options for representation:

| Storage Type | SQL Definition | Ideal Use Case | Pros | Cons |
| :--- | :--- | :--- | :--- | :--- |
| **BLOB (Binary)** | `BLOB SUB_TYPE BINARY` | High-dimensional vectors (e.g., 768 to 1536+ dimensions like OpenAI/HuggingFace). | Unlimited size, out-of-line storage reduces row-width fragmentation. | Slightly higher disk page traversal overhead for small rows. |
| **VARCHAR (Octets)** | `VARCHAR(N) CHARACTER SET OCTETS` | Low-dimensional vectors (e.g., 128 to 384 dimensions like Word2Vec/fastText). | Fast inline access, fits entirely in the data page. | Strictly capped at 32,767 bytes total (approx. 8,191 floats). |

### BLOB-based Table Schema
```sql
CREATE TABLE document_embeddings (
    doc_id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(255) CHARACTER SET UTF8 NOT NULL,
    content BLOB SUB_TYPE TEXT,
    embedding BLOB SUB_TYPE BINARY NOT NULL
);
```

### VARCHAR-based Table Schema
For a 128-dimensional vector ($128 \times 4 \text{ bytes} + 4 \text{ bytes header} = 516 \text{ bytes}$):
```sql
CREATE TABLE image_features (
    image_id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    file_path VARCHAR(500) CHARACTER SET UTF8 NOT NULL,
    features VARCHAR(516) CHARACTER SET OCTETS NOT NULL
);
```

## 2. Advanced SQL Examples

### A. Exact k-NN Search with Multiple Metrics
The following query shows how to search for the nearest documents to a query vector, comparing multiple distance calculations simultaneously:

```sql
SELECT 
    doc_id, 
    title, 
    vector_l2_distance(embedding, vector_from_text('[0.15, -0.02, 0.44, 0.81]')) AS l2_dist,
    vector_cosine_distance(embedding, vector_from_text('[0.15, -0.02, 0.44, 0.81]')) AS cosine_dist,
    vector_inner_product(embedding, vector_from_text('[0.15, -0.02, 0.44, 0.81]')) AS inner_prod
FROM document_embeddings
ORDER BY cosine_dist ASC
OFFSET 0 ROWS FETCH NEXT 5 ROWS ONLY;
```

### B. Hybrid Search: Combining Vector Distance and Text Filtering
In many applications, you want to perform semantic search restricted by metadata (e.g., category, date range, or prefix match):

```sql
SELECT 
    doc_id, 
    title,
    vector_cosine_distance(embedding, vector_from_text('[0.05, 0.12, -0.88, 0.41]')) AS score
FROM document_embeddings
WHERE title LIKE 'AI%' OR title LIKE 'Machine Learning%'
ORDER BY score ASC
OFFSET 0 ROWS FETCH NEXT 10 ROWS ONLY;
```

### C. Normalizing Vectors in SQL
Cosine similarity is mathematically equivalent to the dot product if the vectors are normalized (magnitude = 1.0). You can normalize a vector on insertion or runtime:

```sql
-- Query to normalize and inspect magnitude
SELECT 
    doc_id, 
    title, 
    vector_norm(embedding) AS original_magnitude
FROM document_embeddings;
```

## 3. Computed / Expression Indexes

Firebird supports indexing on expressions. While exact k-NN queries must scan all rows, you can drastically speed up queries that filter on vector magnitude (e.g., separating short, uninformative query vectors from dense ones) by indexing the norm:

```sql
-- 1. Create a computed index on the vector norm
CREATE INDEX idx_doc_embedding_norm 
    ON document_embeddings 
    COMPUTED BY (vector_norm(embedding));

-- 2. Execute a query that leverages the index (check the index search path in ISQL)
SELECT doc_id, title, vector_norm(embedding) AS magnitude
FROM document_embeddings
WHERE vector_norm(embedding) BETWEEN 0.99 AND 1.01;
```

## 4. Real-World Python Integration

The following Python script demonstrates how to generate embeddings using the HuggingFace `sentence-transformers` library, insert them into a Firebird 6 database, and execute semantic similarity searches.

> [!NOTE]
> Make sure you install the Firebird driver and transformers library before running:
> `pip install firebird-driver sentence-transformers`

```python
import os
from firebird.driver import connect, driver_config
from sentence_transformers import SentenceTransformer

# 1. Initialize sentence transformer model (produces 384-dimensional vectors)
print("Loading semantic model...")
model = SentenceTransformer('all-MiniLM-L6-v2')

# 2. Database Connection Parameters
db_config = {
    'host': 'localhost',
    'database': '/opt/firebird/test_db/semantic_search.fdb',
    'user': 'SYSDBA',
    'password': 'masterkey'
}

# Ensure UDR client configuration is set if needed
# driver_config.server_defaults.host.value = db_config['host']

# 3. Create Connection & Schema
print("Connecting to Firebird...")
con = connect(
    host=db_config['host'],
    database=db_config['database'],
    user=db_config['user'],
    password=db_config['password']
)

cur = con.cursor()

# Create table and register UDR functions if not already done
try:
    cur.execute("""
    CREATE TABLE kb_articles (
        id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        body BLOB SUB_TYPE TEXT,
        embedding BLOB SUB_TYPE BINARY
    )
    """)
    con.commit()
    print("Table created successfully.")
except Exception:
    con.rollback()

# 4. Insert Semantic Data
articles = [
    "How to configure Firebird database caching parameters.",
    "Using C++ UDR plugins to extend relational database functionality.",
    "Optimizing SQL queries with expression and computed indexes.",
    "Baking sourdough bread at home with wild yeast starter."
]

print("Generating embeddings and inserting articles...")
for article in articles:
    # Generate float list
    vector = model.encode(article).tolist()
    # Format list as a string representation like '[1.0, 2.0, 3.0]'
    vector_str = "[" + ",".join(map(str, vector)) + "]"
    
    # Insert utilizing vector_from_text
    cur.execute(
        "INSERT INTO kb_articles (body, embedding) VALUES (?, vector_from_text(?))",
        (article, vector_str)
    )
con.commit()

# 5. Execute Semantic Search
query = "How do I speed up SQL queries?"
query_vector = model.encode(query).tolist()
query_vector_str = "[" + ",".join(map(str, query_vector)) + "]"

print(f"\nSemantic Query: '{query}'")
cur.execute("""
    SELECT body, vector_cosine_distance(embedding, vector_from_text(?)) as distance
    FROM kb_articles
    ORDER BY distance ASC
    ROWS 2
""", (query_vector_str,))

for row in cur.fetchall():
    print(f" -> Distance: {row[1]:.4f} | Article: {row[0]}")

con.close()
```

## 5. Real-Time Sidecar HNSW Integration

The optional background sidecar daemon (`fbvector_sidecar`) listens for incoming TCP packets on port `5005` to synchronize an in-memory HNSW index. This avoids sequential scans for very large datasets ($100k+$ vectors) and yields sub-millisecond ANN querying.

### Trigger Setup for Automatic Sync
Register the following triggers on your vector table to automatically stream mutations to the daemon:

```sql
-- Trigger for Inserts / Updates
CREATE OR ALTER TRIGGER trg_kb_articles_sync_aiu FOR kb_articles
ACTIVE AFTER INSERT OR UPDATE POSITION 100
AS
BEGIN
    -- action = 1 (Insert/Update)
    SELECT vector_sidecar_sync(new.id, 1, new.embedding) FROM rdb$database;
END;

-- Trigger for Deletes
CREATE OR ALTER TRIGGER trg_kb_articles_sync_ad FOR kb_articles
ACTIVE AFTER DELETE POSITION 100
AS
BEGIN
    -- action = 2 (Delete)
    SELECT vector_sidecar_sync(old.id, 2, NULL) FROM rdb$database;
END;
```

### Python Sidecar Query Client Example
You can query the HNSW graph directly via socket communication from your backend server for sub-millisecond search times:

```python
import socket
import struct

def query_sidecar_knn(query_vector, k=5, host="127.0.0.1", port=5005):
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.connect((host, port))
    
    # MAGIC_QUERY = 0xF1B10002
    magic = 0xF1B10002
    dim = len(query_vector)
    
    # Header format: uint32_t magic, uint32_t k, uint32_t dim
    header = struct.pack("<III", magic, k, dim)
    # Payload format: float values
    payload = struct.pack(f"<{dim}f", *query_vector)
    
    sock.sendall(header + payload)
    
    # Read result count: uint32_t
    res_count_data = sock.recv(4)
    if not res_count_data:
        return []
    res_count = struct.unpack("<I", res_count_data)[0]
    
    results = []
    for _ in range(res_count):
        # Read pair: float distance, uint32_t id
        pair_data = sock.recv(8)
        distance, node_id = struct.unpack("<fI", pair_data)
        results.append((distance, node_id))
        
    sock.close()
    return results
```
